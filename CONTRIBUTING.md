# Contributing

Thanks for considering contributing! A few guidelines to keep contributions focused and reviewable:

- Open an issue to discuss larger changes before authoring a PR.
- Keep changes small and focused: one logical change per PR.
- Add tests for new functionality where applicable.
- Update `README.md` or relevant docs when adding features or operational behavior.
- For dbt model changes, include a short note describing the analytic value and any schema/migration implications.

When opening a PR include:

- Summary of the change and why it matters.
- List of files changed and the impact on ops or consumers.
- Any migration steps or data considerations.

Maintainers will review and request changes as needed. Thanks!
